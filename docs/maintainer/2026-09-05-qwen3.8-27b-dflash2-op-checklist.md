## 2. 统一 workload、索引与数值边界

### 2.1 运行 extent

| 符号 | 含义 | 支持范围 |
|---|---|---|
| B | active requests | 1..8 |
| K | 启动选定的 draft count | 1..15，推荐 7 |
| W | proposal/verify 物理 block width | K+1，2..16 |
| T | backbone/target matrix columns | W*B，最大 128 |
| U | mask-head/selector matrix columns | K*B，最大 120 |
| P_b | 每请求可验证 draft extent | 0..K |
| Q_b | target live input columns | P_b+1 |
| A_b | accepted draft count | 0..P_b |
| L_b | provisional output count | A_b+1 |
| N_b | Frontend 最终提交数 | 0..L_b |
| W_c、B_c | context materialization 物理布局 | decode W_c=1..16、B_c=1..8；prefill W_c=1..2048、B_c=1 |
| T_c | context projection columns | W_c*B_c；prefill 最大 2048 |
| N_lane | pending-feature lane capacity | startup-fixed 1..8，且 >=B |
| S_state | StateImage slot capacity | startup-fixed，覆盖本轮 state selectors |

同一 Engine 的物理 W 由选定 K 决定；不能为全部配置计算有效 W=8 或 W=16 来规避扩展。
Proposal attention 可使用 valid_columns=W，target attention/GDN 使用 Q_b，context append
使用 counts=N_b。W_c 是 pending storage/gather extent，不能由 accepted draft count 替代；
all-accept 会提交 K+1 个 target input rows，必须保留最后一行 feature。

性能输入域以 `{(K+1)*B}` 和 `{K*B}` 的实际乘积集合定义。纯矩阵 Op 可以按相同列数去重；
卷积、attention、GDN 和状态 Op 必须保留 W/B 划分以及 device counts。已有 Linear 类 Op 的
任意正 T 合同继续成立；最大 128/120 是本轮产品性能范围，不是这些合同的新上限。

### 2.2 固定模型 geometry 与张量布局

```text
hidden H=5120; MLP I=17408; target feature H_f=25600
draft Q=32*128=4096; K/V=8*128=1024; five local layers; window/capacity=2048
conv groups=320; group width=16; taps=2; sides=2
selector candidates M=16; rank R=256
physical vocab=248320; valid global ids=0..248076; optimized head rows=131072

proposal residual       BF16 [5120,W,B]
finish_delta            BF16 [320,2,W,B]
packed mask hidden      BF16 [5120,U]
candidate ids/scores    I32/FP32 [16,K,B]
projected selector h    BF16 [256,K,B]
drafts / proposal q     I32 [K,B] / FP32 [16,K,B]
target logits           BF16 [248320,W,B]
pending features        BF16 [25600,W,N_lane]
```

Artifact Weight `[N,C]` 表示 `[output rows,input columns]`；runtime Tensor 的 ne[0] 连续。
Base kernel 保留 artifact `[side,tap,channel]=[2,2,5120]`，runtime view 为 `[5120,2,2]`；
codebook 保留 artifact `[vocab,rank]`，runtime view 为 `[256,248320]`。这些固定 8/16/256
等模型维度不能随运行 W/K 一起替换。

### 2.3 保持的数学与实现自由度

- Dynamic convolution 仅在当前 request block 内跨相邻位置，位置零没有 previous tap；
  finish 消费同一 prepare 的 output-side delta，无跨轮卷积状态。
- Proposal SWA 为 `abs(key_position-query_position)<2048`；当前 block 的有效 query 互相
  可见。Q/K 使用 plain head RMSNorm 和 theta=1e7 的 full-D128 split-half 1-D RoPE。
- Final norm-pack 跳过 anchor；top-16 使用 score 降序、同分 global-id 升序。Optimized
  head 的 row id 先映射为 global id，再供 selector 使用。
- Selector 是实际前驱条件下的逐位 walk；保留实际抽样的 FP32 q。逐 row、部分预计算、
  完整 lattice 均可作为同一 Op 的内部方案，不能换成独立逐位置 unary argmax 或 Viterbi。
- Sparse accept 使用实际 q 的 p/q rejection 和 `(p-q)+` correction；N 而非 P/A/L 决定
  最终持久状态提交。Proposal RNG purpose 与 target accept/correction/bonus 分离。
- Norm/conv prepare、projection/conv/residual、norm/RoPE、norm/pack、projection/top-k、
  selector walk 和五层 context materialization 保持闭合 public 边界。Private staging、
  reduction、tiling、launch 数由 qualified route 决定，不要求每个融合 Op 只有一个 kernel。
- Oracle 从 represented public inputs 及精确解码的 stored weights 计算完整公式；不可观察
  中间精度作为 implementation profile。OP-07 已去掉 raw K 的额外语义舍入；最终 BF16 K、
  `FP16_RNE(BF16)` V storage cast、public BF16 outputs 和实际 FP32 q 保持各自边界。

### OP-23 — 修复结果

**性能：** RTX5090/sm_120a/CUDA13.1，cold Graph、warmup4/repeat25，22 个代表点。小列数基本持平：W8 T16 845.056→843.008µs，FP8 T24 806.144→804.128µs；少量局部变化不继续补丁化。W8 C96 的补充对照：T65 1647.58→1453.82µs，T96 1694.53→1439.01µs，均为一个 Graph kernel 节点且无需 scratch。结果只支持 dense head Op，本项关闭。

### OP-29 — 验收结果

**合同与路线：** argmax 对每个物理列的 BF16 logits 在 valid_rows=248077 内做精确比较，tie 取最小 global id；它不负责排除 target 的无效 token 列。保留一次输出初始化 + 2-D tiled atomic winner reduction；小 aggregate 用较大 block 减少 atomic 竞争，较大 aggregate 的完整 vocab 用 128 threads 提供并行度。无需按 W 增加实例。

**验收：** `ninfer_argmax_test` 10 个 fixture 通过，包含 target T1/2/8/9/15/64/128、shortlist companion 和 T128 改变 logits 的 Graph 重放。精确 oracle 检查所有输出列、跨 tile tie、全负值与全相等输入。修正原测试中 padding poison 不一定大于高编号列最大值的问题，现在每列 padding 都能击败合法最大值，直接保护 valid_rows 排除规则；输入保持和 guards 通过。未改 kernel，无新性能疑问或加速主张，本项关闭。

### OP-30 — 验收结果

**合同与路线：** target 使用 D256/R64、Q24/K4 的 partial RoPE；仅前 64 维旋转，后 192 维保持原位。Text 1-D 与 Text/Vision MRoPE 的三轴位置按各自公式验收，不能借用 draft D128 full-head RoPE。保留现有成对/单 tensor 和 stride 分工，未引入按 W 分派。

**验收：** `ninfer_rope_test` 通过。新增两种位置模式 × W2/7/16 × B1/B8 的 12 个真实 target fixture，flatten 后各 lane 有不同绝对起点；包含 padded token stride 和最大 T128 Graph 重放。旋转维对唯一 FP64 oracle 检查，非旋转维、token padding 和 positions 逐位保持；原数值判据及既有单 tensor、35B/DFlash/Vision 回归通过。kernel 未改，无新性能主张，本项关闭。

### OP-31 — 验收结果

**合同与路线：** 完整公式为 `x *= sigmoid(gate)`，与 GDN 的 RMSNorm×SiLU 是不同 Op；调用前 BF16 x/gate 是 oracle 输入，x 原地更新，gate 不变。保留现有按向量对齐和 contiguous extent 执行的逐元素 kernel，无需 W/B 专用模板。

**验收：** `ninfer_sigmoid_mul_test` 10 个 fixture 通过：target D6144 的 T1/2/8/16/48/64/128 和 T128 Graph 重放，另保留 D4096 与数值边界回归。直接对独立 FP64 sigmoid 乘法公式检查；每次 Graph 前恢复原 x，验证一次原地转换，gate 保持和 guards 通过。原 pointwise criterion 不变；无 kernel 修改或新性能主张，本项关闭。

### OP-32 — 验收结果

**合同与调用方式：** offset Op 的 delta 是 device scalar；每个 lane 用自己的 source/destination vector view 和 delta 调用，不能把不同 delta 的 batch 展平后只调用一次。三轴 MRoPE 在一个 lane 内按完整连续位置 vector 处理，DFlash2 F+i cache position 的所有权仍独立。

**验收：** `ninfer_position_test` 通过。新增 W2..16×B1/B8×1/3轴×原地/非原地的 120 个组合，以及改变 device delta 的 W16/B8 Graph 重放；所有元素对整数加法精确比较，源、delta 与 guards 保持。既有 fill、负 delta 和长 vector 回归通过。保留单一逐元素 kernel；采用整数 exact oracle，不另做 FP64、性能搜索或 Engine 接线工作，本项关闭。

### OP-33 — 验收结果

**合同与路线：** 每行一个 anchor、W−1 个 mask，位置为 `length + min(j,valid−1)`；proposal dense 时 valid=W，target partial 时 invalid tail 重复最后有效位置。DFlash2 使用 mask_id=248070，旧 DFlash 的 248077 只保留为另一 caller 值的回归。每 lane 一个 warp 的现有 kernel 已覆盖 W≤16，无须新增 route。

**验收：** `ninfer_prepare_masked_block_test` 通过：新增 W2..16、B1/B8、dense/ragged 及中间 batch，共 61 个 target fixture，W16/B8 Graph 改变 anchor、length、valid 后重验。所有 ids/positions 精确比较，valid=1 和全部输入保持、guards 得到检查；既有 I32 最大合法位置边界回归通过。无 kernel 修改，不开展 benchmark campaign，本项关闭。

### OP-34 — 验收结果

**合同与路线：** ids-only 与 ids+positions 两种公开 form 分别对同一整数索引公式验收。P=0 只有 anchor 有效；其余物理 ids 尾部填 anchor，position 尾部重复 base+P，保持 target 固定 W=K+1 的安全输入。保留现有简单 prepare kernel，不把 P 当成物理宽度或更改 draft 存储步长。

**验收：** `ninfer_speculative_round_test --transforms-only` 通过。K1..15×B1/B8，每行轮流覆盖所有 P=0..K，共 270 个前缀场景；两个 form 的所有元素均 exact 对照，输入/guards 保持。K15/B8 的同一 Graph 随 device P 改变重放。新增 focused 入口只跳过无关 sampling/accept 测试，默认完整测试内容保留；本项不修改 acceptance 算法，不重复其 benchmark 或 FP64 检查。

### OP-35 — 验收结果

**合同：** 这是 BF16 位拷贝 gather；最终提交 N>0 时由 caller 提供 selector=N−1，不能把 accepted draft count 直接当 selector。N=0 时 schedule 不调用本 Op，不构造 −1 索引。

**验收：** `ninfer_speculative_round_test --transforms-only` 通过。新增 D5120、W2..16×B1/B8 的 30 个 fixture，每 lane 轮流覆盖 N1..W（270 个选择场景），包括最后一列和非满提交；W16/B8 Graph 改变 device selectors。所有 BF16 位模式精确比较，含源数据/selector 保持和 guards，已有 companion gather/remap 回归通过。保留现有按 D 和 batch 复制的 kernel，无 W 专用 route、浮点容差或性能搜索，本项关闭。

### OP-36 — 验收结果

**合同与路线：** continuation scatter 是精确 BF16 column copy；compact source 的第 b 列写入指定 owning slot，其他 slots 保留原位。D5120 使用现有 16-byte 向量拷贝，不增加 N/W 专用分派；零提交 lane 由 schedule 排除于这组 gather/scatter 调用之外。

**验收：** `ninfer_scatter_test` 通过。新增 W2/7/16×B1/B8 及 W5/B3，共 7 个 gather→scatter 组合 fixture，源 hidden 为实际 `[5120,W,B]`；每个合法 N−1 selector 都进入重排后的 state slot，并完整比较全部 11 个 slot。W16/B8 用同一 Graph 改变 device selectors，未选 slot、输入/lanes 和 guards 精确保留；原 scatter/extract 回归通过。无 kernel 修改或性能搜索，本项关闭。

### OP-37 — 修正与验收结果

**合同与路线：** fold 的 FP32 recurrent state 与 BF16 conv history 必须逐位等于同一完整 record-producing block 的第 N 个 snapshot；N=0 保留 destination 原值，不复制 source，也不读取该行 records/state。保留一个按 layer/row/head/state tile 并行的 recurrent fold kernel，内部按 N 顺序执行与 snapshot 相同的 FP32 transition，融合 conv tail_3 发布。W 为运行时值，仅两个已注册模型 geometry 实例；不引入会改变 FP32 状态位的并行前缀重排。

**验收修正：** 删除 fold 的额外 FP64 oracle。原浮点 vector `==` 改为 `memcmp`/uint32 位比较，并加入初始负零。参考执行推进同一个完整 W 块、保存第 N 步状态；真实 target 集成 fixture 在 W16 做 Q4/Q5 projection 和 conv snapshot，然后逐 token 生成全部 recurrent snapshots，从中选择 N−1。连续三轮提交 N1/15/16 的 48 层 state、conv、q/k/v/z/output 位比较通过，没有重跑宽度 N 的投影。

**范围与效率：** `ninfer_gdn_replay_fold_test` 全部通过：11 个 all-layer fixture（27B/35B），包含 W2/3/6/7/16、B1/2/4/8、N0/1/2/3/中间值/15/16、同址及不同 source/destination、最高 slot、inactive slots、records 只读和 guards。W16/B8 同址 Graph 重放前用 GPU copy 恢复初始 state；host row descriptors 按值捕获的合同已写入头文件。N0 的不同 destination 预期修正为其原值。检查 outer guards 不再额外下载整个多 GB state pool，数值/状态覆盖不因此减少。

**有效性能证据：** 修复 benchmark 仍以 `{slot,commit}` 初始化三个字段的 row，导致 commit_columns 默认为 0 的错误；现在显式设置 `{source,destination,commit}`，旧错误输入的 fold 时延作废。RTX5090/sm_120a/CUDA13.1，cold eager CUDA-event 完整 48 层 fold、warmup4/repeat25；W2/16×B1/B8×one/dense/mixed 共 12 点。W16/B1 全提交 277.73µs，W16/B8 全提交 1838.37µs、mixed 1463.55µs；约 1.31–1.44TB/s 的 state 逻辑读写量支持保留现有单次 launch 分工。kernel 未变，无新增加速或 Engine 性能主张，本项关闭。

## 5. 重新关闭项目的要求

### 5.1 先确定方案，再做有限比较

1. 写明当前问题、真实输入域、少量候选机制及选择依据。浮点精度、codec、request 边界、
   counts/物理宽度和 workspace 是约束，不能以简化分派为由破坏。
2. 将运行时 live extent 与编译 tile 容量分开评估。固定硬件 geometry、格式和合法对齐的
   必要分工可以保留；逐 T/K/W 特化、非连续回跳、单形状例外必须说明相对更少配置的增量收益。
3. 使用完整公开 Op、相同 fixture 和 cache 条件比较。先测短/推荐/最大 K、B1/B8 及能区分
   方案的边界；纯矩阵按实际 T/U 去重，attention/state 保留 W/B/context/counts。
   已能区分方案时停止扩充候选，不为每个相邻点重复扫配置。
4. 短调用用重复 Graph 或图内事件排除 host 提交间隙；冷缓存离散档、单个异常 median 和
   未超过波动的差异不足以新增路线。保留少量路线不需要证明它是理论最小数量。
5. 额外配置若保留，记录其适用区间、完整 Op 的稳定收益、scratch/launch 取舍及原因。
   不能只以“这个点最快”或“补平台阶”作为理由；也不预设删除配置可以无损提速。
   不设机械的统一模板上限或统一百分比门槛，不为达成数字牺牲相关性能。

### 5.2 Qualification 与证据复用

- 先从 Op 的可观察承诺选择验收参照。数学计算使用完整公式及实际 stored scale 的独立
  FP32/FP64 oracle；精确转换检查地址/位模式；概率过程检查条件分布、RNG 和可许可输出。
  ReplaySSM OP-23/24/37 以对应 snapshot 执行为参照，要求输出和提交状态 bit 一致；
  N 列提交对应同一完整块的第 N 个 snapshot，不能另跑宽度 N 的投影。无需为这种等价性
  再做 FP64 对照；若修改 snapshot 的数学实现，则单独验证其数学合同。
  数值判据变化须有格式/误差依据，不能为某个 kernel 放水。
- 宽度验证按改变的机制选择：逐 W 实例/分派表覆盖所有可达 W；运行时宽度的共同实现
  覆盖短/长/奇数 W、request 边界、ragged/zero/full 等能暴露索引或状态错误的场景。
  纯矩阵重点覆盖每条生产 route 和改变的边界。相同 T 不同 W/B 在 state/conv/attention 中
  不是相同输入；代表性证据足以支撑结论时，不机械展开所有变量的笛卡尔积。
  未改变且证据仍适用的行为无需重跑全部旧实验。
- 改变 workspace 或调用分解时，复验区间 query、实际峰值、scope 归还和同址 Graph
  capture/replay。Capacity 必须覆盖所有可达 envelope，不能只查最大 W/B 的满块路线。
- 只在已识别 kernel 的具体资源问题会改变方案时用 NCU；此阶段不要求未接入的 Engine
  或 nsys。排他 GPU 计时；编译使用 `cmake --build <dir> -j`。
- 每项记录合同/格式、实现机制与实例规模、代表性性能取舍、实际通过的数值/状态检查、
  仍存在的限制和下一步。记录选定方案的证据，不保留逐点全曲线、失败候选流水或计时噪声日记。
  Benchmark 的可用命令以 [bench reference](../../bench/README.md) 为准。
